# lotto-lab

로또 6/45 + 연금복권 720+ 데이터 수집·분석·번호 추천 도구 (엔진 v2, 2026-09).
동행복권 공개 API → 로컬 엔진이 회차당 1번 추천 생성 → GitHub 미러 → 구글 시트가 가져와 표시·채점.

## 구성

| 파일 | 역할 |
|---|---|
| `lotto_lab.py` | 엔진 — 수집, 번호 인기도 모형, 추천 생성(회차당 1회), 채점, 리포트 |
| `lotto_sheets.gs` | 구글 시트 대시보드 — 미러에서 가져와 표시·채점·편중 감시 (번호를 직접 만들지 않음) |
| `tools/check_engine.py` | 불변 조건 검사 — **규칙을 바꾸면 반드시 실행** (편중 재발 시 실패) |
| `tools/backtest.py` | 워크포워드 백테스트 v1/v2/무작위 → `data/backtest.csv` |
| `tools/test_sheets.js` | 시트 스크립트 종단 테스트 — **`.gs`를 고치면 반드시 실행** (`node tools/test_sheets.js`) |
| `data/lotto_history.csv` | 로또 전 회차 (번호, 1~5등 당첨자 수, 총판매액) |
| `data/pension_history.csv` | 연금복권 720+ 전 회차 |
| `data/lotto_picks.csv` / `pension_picks.csv` | 추천 기록부 (회차당 1회, v1 이력은 로그에서 복원) |
| `data/popularity.csv` | 번호별 인기도 |
| `data/scoreboard.csv` | 실전 성적 (공식 / 대조군 / v1) |
| `report.md` | 마지막 실행 리포트 |

## 실행

```
python lotto_lab.py              # 갱신 + 추천(이미 있으면 유지) + 채점 + 리포트
python lotto_lab.py --no-fetch   # 저장 데이터로 추천·리포트만
python lotto_lab.py --strength 1 # 분할 회피 강도 (0=무작위 ~ 2, 기본 0.5)
python lotto_lab.py --sets 10    # 로또 10세트 (5세트 단위로 번호 중복 없음)
python lotto_lab.py --pension 30 # 연금 후보 30순위
python tools/check_engine.py     # 엔진 불변 조건 검사
python tools/backtest.py         # 백테스트 (약 3분)
```

필요 패키지: `pandas`, `numpy`, `scipy`, `requests`

## 엔진 v2 원리

**1. 적중 확률은 바꿀 수 없다.** 모든 조합의 1등 확률은 1/8,145,060. 백테스트에서 v1·v2·무작위 모두
평균 적중 0.80개(이론값)로 같다. "잘 맞히는 엔진"은 존재하지 않는다.

**2. 분할 회피 — 번호 인기도 모형.** 무작위 구매라면 5등(3개 일치) 당첨자 기대값이 판매수로 정확히
정해진다. 회당 ~270만 명이라 잡음이 거의 없어, 실제가 기대보다 많았던 회차의 당첨번호 = 많이 찍힌 번호로
역산할 수 있다(능형회귀, 최근 520회). 과거로 학습해 미래 200회를 예측한 상관 **0.83**.
인기 번호는 7·12·11·3·17·9(생일·행운의 수), 비인기는 36·29·45·43·44.
당첨번호가 가장 인기 있던 5분위 회차는 1등이 기대의 1.16배, 가장 비인기 5분위는 0.89배였다.

**3. 분산 — 30개 번호, 구간 비례.** 5세트 30개 번호를 겹치지 않게, 구간(1-9/10대/20대/30대/40대)별
크기 비례로 배치한다. 구간 편중이 구조적으로 불가능하고, 5세트가 같이 맞고 같이 틀리는 일이 줄어
"주당 5등 이상 1건이라도" 확률이 11.9%(무작위 11.4%)로 오른다. 기대 상금은 동일.
구간 안에서는 인기 번호를 덜 뽑는다(강도 0.5 — 1.0 이상이면 7·12번이 거의 안 나와 편중으로 보임).

**4. 연금 — 끝자리 분산.** 연금 1등은 1장당 고정 연금이라 분할이 없다 → 번호는 균등 무작위.
등수가 끝자리부터 정해지므로 10순위 단위로 끝자리 0~9를 한 번씩, 끝 2자리는 전 후보가 서로 다르게,
조는 5순위 단위로 1~5조 한 번씩 배정한다.

### v1(2026-07~09)에서 고친 문제

| 문제 | 원인 | v2 |
|---|---|---|
| 23~31번이 0.28배로 거의 안 나옴 | 설명력 1.4%(R²=0.014) 모형을 과최적화 + '1~22번 2~4개' 필터와 충돌 | 구간 비례 배치로 구조적 차단 |
| 편중 대가로 얻은 분할 회피 효과 0.8%뿐 | 20번대는 실제로 평균 인기(0.995). 엉뚱한 번호를 피함 | 검증된 번호 인기도 모형, 효과 2% |
| 연금 후보 64%가 끝자리 4 | 미달빈도 점수 정렬이 최고점 숫자로 수렴 | 끝자리 강제 분산 |
| 판매액이 실제의 절반 | API의 당첨금 배분액 필드를 판매액으로 읽음 | 총판매액 필드 사용 |
| 실행마다 같은 회차 추천이 바뀜 | 리포트가 매번 새로 생성 | 기록부에 회차당 1회만 |
| 리포트와 시트 번호가 다름 | 시트가 구 계수를 하드코딩한 별도 JS 엔진으로 생성 | 시트는 기록부를 가져오기만 |
| 토요일 결과를 5일 늦게 반영 | 21:30 실행 시점에 결과 미게시(9/26) | 재시도 트리거 추가 |

## 자동 갱신 (Windows 작업 스케줄러)

작업 `lotto-lab-update` → `run_hidden.vbs`(창 없이) → `run_update.cmd` → `lotto_lab.py` → git push:

- 로또: **토 21:30 · 토 23:30 · 일 10:00** (결과 게시가 늦어도 다음 시각에 잡힘)
- 연금: **목 20:30 · 금 10:00**
- 추천은 회차당 1번만 생성되므로 여러 번 돌아도 번호가 바뀌지 않는다
- PC가 꺼져 있었으면 다음 부팅 때 실행 (`StartWhenAvailable`), 이력은 `logs/update.log`

## 구글 시트

> 동행복권은 해외 IP를 차단해 Apps Script가 직접 수집할 수 없다("사용할 수 없는 주소").
> 시트는 공개 저장소 `github.com/LucianaStyle/lotto-lab`의 `data/*.csv`를 가져온다.

설치: 시트 안에서 확장 프로그램 > Apps Script → `lotto_sheets.gs`로 교체 → 저장 → 시트 새로고침 →
[복권분석 > 지금 동기화]. 첫 실행 때 기존 추천 시트는 `로또추천_v1`·`연금추천_v1`로 보존되고,
로또이력은 새 스키마로 다시 받으며, 트리거가 3시간 주기로 바뀐다.
(반드시 시트에 바인딩된 프로젝트여야 한다 — 독립형은 getUi 오류.)

| 시트 | 내용 |
|---|---|
| `로또추천` / `연금추천` | 이번 주 추천 + 지난 회차 채점 (맞은 번호 초록, 보너스 호박, 연금은 일치한 끝자리만 초록) |
| `성적` | v2·v1 누적 성적, 적중 개수 분포를 이론 기대 건수와 나란히 |
| `편중감시` | 구간 비중·번호별 빈도·연금 끝자리 분포 (균등 = 1.00, 색으로 편중 표시) |
| `번호인기도` | 45개 번호 인기도 격자 (빨강 인기 / 파랑 비인기) |
| `검증` | 백테스트 표 + 로컬 엔진 실전 기록(대조군 포함) |
| `통계` / `로또이력` / `연금이력` | 참고 통계 · 원본 데이터 (연도 경계선, 2~5등 당첨자 수 포함) |

## 데이터 API 메모 (2026-07 개편 후)

- 로또: `GET /lt645/selectPstLt645InfoNew.do?srchDir=center&srchLtEpsd={회차}` — 회차당 ~10건, 미래 회차는 빈 리스트
  - 총판매액은 `wholEpsdSumNtslAmt`. `rlvtEpsdSumNtslAmt`는 당첨금 배분액(약 400회 이후 판매액의 50%)
- 연금: `GET /pt720/selectPstPt720WnList.do` — 전 회차 일괄
- 구 `common.do?method=getLottoNumber`는 302로 폐기됨, User-Agent 헤더 필수

> ⚠️ 어떤 분석도 1등 확률을 바꾸지 못한다. 구매는 여유 자금 내에서.
